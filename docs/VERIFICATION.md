### Answer-length switch (Short / Balanced / Detailed)

Verified three ways, because a dropdown that silently does nothing is easy to ship:

- the request the UI sends carries `detail: brief|balanced|detailed`;
- the server turns that into a different instruction and a different token budget
  (300 / 700 / 1100 tokens), proved by a spy on the model call **and** by a stub
  model that echoes the budget it received;
- the choice is remembered in `localStorage` and restored after a reload;
- invalid or missing values fall back to balanced, and `ANSWER_MAX_TOKENS` still
  overrides all three presets.

The select also got a custom chevron, brand focus ring and readable option colours,
because the browser default rendered as a thick black box on Windows.

### Bringing in any model

Verified against a local HTTP server serving a stand-in GGUF (GGUF magic + 3 MB of bytes):

- `POST /api/models/download-url` streams the file into `models/TinyLlama-1.1B-Chat-Q4_K_M.gguf.part`,
  renames it on completion, and writes the choice to `selected.json`;
- `/api/models` then reports `selected_id = file:…/TinyLlama-…gguf` and lists it as downloaded;
- a link that returns HTML is refused with "That link is not a GGUF model file…" and leaves no file behind;
- `ftp://`, `file://` and bare hosts are rejected before any network call; `../` in a link cannot escape
  the models folder;
- the low-disk check compares `Content-Length` with free space and refuses before writing gigabytes;
- Profile shows the models folder and free space, its **Open folder** button reaches the server
  (falls back to printing the path when no file manager exists, which is what happened in this sandbox),
  and the browser blocks a non-link before it is sent.

## 3. Browser-level checks (real page, real JS)

The workspace, summaries, profile, landing, login and forgot pages were loaded in a
DOM environment (jsdom) with the real scripts against the running server.

- Workspace: library renders, 4 question chips render, 3 quick actions, clicking a
  chip produces an answer, the asked chip disappears, MCQ action answers, a typed
  question answers, "clear chat" empties the thread and keeps the input usable,
  **no JavaScript errors**.
- The same workspace run against a server with **no model**: answers fall back to
  exact quotes and the label reads `Passages only (model off)`.
- Summaries page: 7 brief cards, mode label, 5 evidence passages, download links.
- Profile page: name, uploaded files, 3 model choices, RAM-based recommendation,
  apply button disabled until a choice, no `undefined` in model rows.
- Landing / login / forgot: tabs switch, register mode shows the name field, client
  validation raises both field errors, no JavaScript errors.

## 5. Bugs found by this pass (and fixed)

1. Model-download polling code was duplicated in three handlers, including a
   recursive interval inside `pollDownload()`.
2. The Profile model picker saved a choice for an undownloaded preset without
   starting the download.
3. Model rows could print `undefined MB · undefined`.
4. Upload progress froze on one value.
5. Hindi/Chinese filenames were rejected as "not a PDF".
6. A `.pdf`-named text file reached the PDF parser.
7. Raw Python exception text leaked into upload/answer errors.
8. `sanitize_answer` deleted `[Figure 3]` / `[Table 2]` along with numeric refs.
9. Answers showed raw Markdown (`**`, `##`, `|---|`, backticks).
10. The model-mode label was hidden whenever evidence chips were present.
11. Summary `notice` dumped internal exception text.
12. The model chip could display a Windows folder path.
13. `start.bat` failed when only the `py -3` launcher existed.
14. The 20 MB upload limit was too small for scanned papers.
15. Project report and slide deck still described the Groq + Supabase version.
16. Five lint findings (zips without `strict=`, `raise ... from`, duplicate stopword).
